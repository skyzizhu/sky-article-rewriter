## 验证设计

一个新的独立上下文只接收冻结候选技能、4份输入及实际任务，不提供期望答案、旧评测结论或建议修法。没有按第一次输出继续提示、挑选更好结果；每项保存草稿、简短审稿修订记录和交付稿。A、B、C由完整短文重构，D以给定完整旧稿执行审稿。

| 输入 | 内容 | 观察重点 |
|---|---|---|
| A | 产品目录页图片加载测试说明 | 首屏与全页区别、样本与适用范围、必要机制、尚未测量的效果 |
| B | 图书馆预约试点问答 | 自愿反馈口径、提案与已实施、持续分歧、下一步范围 |
| C | 第一人称生活短文 | 保留场景、时间和开放结尾；已清楚的内容不强行改写 |
| D | 小桥两次封闭纪实及已有稿 | 核心偏移、转述与亲见、事件时点、待查状态、套话与重复释义 |

完整输入见 [inputs.json](inputs.json)。**全部为本次新编虚构控制材料**，没有真实采访、实际性能试验或真实读者参与。一个上下文处理四项不等于四次独立运行；短文表现也不能代表长文稳定性。

候选指令与输入指纹见 [protocol.json](protocol.json)。完成后由协调者核对原文、草稿、交付稿和实际差异，分别记录信息保留、冗余处理及残余问题，不用字数下降或生成者自述“已检查”代替质量判断。前轮文章及评测保持原样。
