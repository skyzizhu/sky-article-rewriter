# 文章精读重构 · sky-article-rewriter

把已有文章或播客转录，重构为**读得懂、跟得上、愿意继续读**的文章。

它会先理解原文，识别阅读障碍，再按读者的理解顺序组织内容。难懂的概念可以借助熟悉的相似案例解释；人物、事件和背景则按需要重新交代。成稿保留原意和重要限制，默认可以独立阅读。

这是一个供 Codex 使用的 Skill，由提示词指令与参考指南组成，无需 API Key 或额外运行依赖。

## 能做什么

- **保持核心表达：** 先确认原文主旨，再安排标题、开篇、正文和结尾；允许有归属、有依据的延伸，但不让新观点替代原文主题。
- **拆解内容：** 识别人物、事件、时间、地点、环境、概念、观点、依据和段落作用，只分析与理解有关的部分。
- **重排结构：** 按理解依赖移动背景、合并重复、展开跳跃步骤；保留必要的事件顺序、操作依赖和揭示关系。
- **解释难点：** 优先利用原有案例；需要时补充贴切的相似案例，讲清对应关系与类比边界。
- **改善阅读：** 让下一段接住读者当前需要了解的信息，减少术语堆积、重复总结和空泛转场。
- **保持忠实：** 分清原文信息与补充解释，不虚构人物经历、对白、数据或引用，不用类比代替证据。

## 适合哪些内容

| 内容 | 处理重点 |
|---|---|
| 采访、播客转录 | 按议题整理，保留说话者、追问、修正和分歧 |
| 技术说明、科普、研究解读 | 按知识依赖解释概念与机制，保留适用条件与证据范围 |
| 技术教程 | 讲清目的与步骤，保持代码、参数和操作依赖准确 |
| 生活经验、随笔 | 保留具体处境、感受和有意义的细节，不把个人体验写成普遍规律 |
| 纪实、人物故事 | 理清人物关系与时空变化，保留信息来源与确定程度 |
| 观点、评论 | 讲清问题、立场、理由、依据及限制 |

混合内容不强塞进一个类型。例如技术播客先整理对谈议题，再解释技术难点；人物采访可以用经历串联，局部保留不同人的判断。

## 安装

将本仓库克隆到本地 Codex 技能目录。下列命令适用于尚未安装本技能的环境：

```bash
git clone https://github.com/skyzizhu/sky-article-rewriter.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/sky-article-rewriter"
```

如果使用了自定义技能目录，请将目标路径替换为对应位置。重新打开一个 Codex 会话后，通过 `$sky-article-rewriter` 调用。

如果已有旧版 `sky-article-deep-reader`，请先备份自己的修改，再将旧目录移出技能目录，避免两个版本同时被选中。仓库中的正式标识为 `sky-article-rewriter`。

## 快速使用

### 默认：重构为完整文章

```text
请使用 $sky-article-rewriter 处理下面的文章。
面向没有相关背景的读者，重组为通俗连贯、循序渐进的完整文章。
按需用相似案例解释难点，保留原意与重要限制。

[粘贴正文、提供可读取的文件或文章链接]
```

只有链接但无法获取正文时，技能会请求提供文本，不会根据标题假装读过全文。播客请提供转录文本或可读取的转录来源；本技能不包含音频转写功能。

### 采访或播客

```text
请使用 $sky-article-rewriter 整理这份播客转录。
按核心议题组织成文章，删去不影响含义的口头重复。
保留嘉宾各自的观点、主持人的关键追问，以及后续修正和分歧。

[转录正文]
```

### 技术文章

```text
请使用 $sky-article-rewriter 改写这篇技术文章。
假设读者没有相关专业背景，从要解决的问题讲起，解释必要概念。
原文案例已经清楚时直接使用，不额外重复举例。
如果包含代码或操作步骤，保持其准确形式和依赖顺序。

[文章正文]
```

### 指定范围、篇幅或输出位置

```text
请使用 $sky-article-rewriter 处理这篇文章。
目标读者：刚接触这个领域的人。
篇幅：约 2000 字，优先讲清核心机制和关键案例。
保留：作者的主要判断、重要依据和限制条件。
请将结果保存为当前项目中的 article-rewritten.md。

[文章正文或文件路径]
```

### 需要逐段带读时

```text
请使用 $sky-article-rewriter 带我逐段阅读这篇文章。
保留原文顺序，解释难点和段落之间的关系，提供必要的原文定位。

[文章正文]
```

## 默认交付

默认面向没有相关专业背景、愿意认真理解的成年人，直接输出完整正文及必要来源。类型判断、内容映射和结构草稿留在内部，不默认交付分析报告，也不要求逐步确认提纲。

可以指定读者背景、阅读深度、篇幅、保留的结构，以及想重点理解的问题。未指定时按内容决定，不套固定节数、字数比例或案例数量。

简单文章只处理明显障碍；复杂内容建立映射并重构；超长内容先掌握全局，再分段写作并统一编辑。默认不保存文件、不生成图片或网页，用户要求时按指定范围交付。

## 处理流程

1. **读取与判断：** 确认材料范围及核心表达，识别内容形式、领域与阅读任务。
2. **拆解与组织：** 找到主线和理解障碍，按需要处理人物、事件、概念、依据及背景。
3. **解释与写作：** 按理解顺序成文，优先用原例，必要时增加有边界的类比。
4. **全篇编辑：** 连接段落，删去没有信息增量的内容，统一术语与人物称呼。
5. **回查后交付：** 对比原句与成稿多出或漏掉的含义，修订后再核对前后承接；全篇合并重复解释，保留重要条件与必要归属。

## 边界与验证状态

- 真实补充案例需要查证来源；假设案例必须说明性质。能否获取外部材料取决于运行环境中的工具与访问权限。
- 改写技术教程不会自动执行命令、安装依赖，也不代表代码已经测试。
- 不凭空补齐原文缺失的信息，不把部分正文称为全篇解读。
- 已完成[九份真实材料的模型评测与定向回归](evaluations/2026-10-18/README.md)，覆盖访谈、散文、小说、政治随笔、技术说明、教程和历史纪实。报告保留基线、新稿、具体缺陷及残余问题；精简输出与未测范围均明确披露。这不是目标读者试读或读完率验证。
- 已完成[第二轮三份长材料、六次独立运行及交叉复核](evaluations/2026-10-18-round2/README.md)：长口述访谈、多人听证和技术报告。六稿均保留核心，回查有实际修正，也留下局部精度及阅读组织问题；草稿、回查、冻结交付稿和残余缺陷全部保留。本轮未修改技能，不宣称效果已稳定。
- 根据第二轮问题，已对第5步做[执行校准与两次小范围验证](evaluations/2026-10-18-step5-calibration/README.md)，明确新增含义、修订承接及跨节去重的实际动作。初次不足和重试残余均保留；这是片段回查验证，不是新版六篇全文重跑。
- “愿意继续读”是设计目标，需要真实读者反馈检验，不承诺读完率或理解效果。

## 反馈与改进

欢迎通过 [Issues](https://github.com/skyzizhu/sky-article-rewriter/issues) 反馈具体问题。建议提供：文章类型、目标读者、可公开的原文片段、对应改写、哪里难懂或拖沓，以及期望的变化。请勿提交未经允许公开的原文或个人信息。

优先修复真实材料中出现的问题：区分单篇编辑问题、规则缺口和执行遗漏，按需精简或修改对应指令，再检查是否影响其他类型文章。文章润色、技能更新及新版试跑分别核验，不将单篇改好视为技能效果已经稳定。
