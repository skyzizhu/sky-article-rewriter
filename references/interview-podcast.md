# 采访与播客转录的改写

## 先整理谁说了什么

内部记录“说话者—议题—主张或经历—限制或修正—来源位置”。有时间戳就沿用，没有就用已有轮次或议题定位。无法确定发言人时说明不明确，不根据观点猜身份。

把同一话题分散的发言归在一起，但先检查后文是否推翻、收窄或修正了前文。受访者先说“都可以”，后说“仅限简单任务”时，整理成带有限定的主张，不能只摘前一句。

## 实际整理动作

| 转录现象 | 怎么处理 |
|---|---|
| “嗯、那个、就是说”等口头填充 | 不影响意思时删除 |
| 同一主张多次出现 | 合并，保留改变判断的条件和有独立作用的例子 |
| 话题来回跳转 | 按议题归组，用明确关系串联；不伪造新的现场问答 |
| 主持人提问很长 | 可压缩背景，保留影响回答的前提 |
| 追问使嘉宾改口或限定答案 | 保留追问与修正的关系，不当作重复删去 |
| 两位嘉宾不同意 | 分别说明立场，不合成为“大家认为” |
| 玩笑、反讽、语气或指代不明确 | 不根据纯文字断定心理或真实立场；关键处保留歧义或说明文本不清 |
| 转录疑似错字、术语误识别 | 可核实才修正；影响理解且无法确定时标明，不能默默猜成结论 |

默认转成围绕核心问题的连贯文章，不巡览所有话题或逐轮复述；旁支按主文件取舍。采用间接转述。只有忠实保留的原话才能作为直接引文，不将跨轮次拼接或润色后的发言放进引号。用户要求保留问答时，在问答框架内整理，不伪造主持人没问过的问题。

## 选择阅读主线

- 以经历为主：人物处境 → 关键选择与变化 → 对相关问题的看法。
- 以知识为主：核心问题 → 必要概念 → 嘉宾解释 → 分歧、条件与未知。
- 以争论为主：争论对象 → 双方分别主张什么 → 依据及分歧所在。

这些是可选路径，不是必须补齐的章节。采访中讨论技术时，按需读取 [technical.md](technical.md)；人物经历复杂时使用 [narrative-and-flow.md](narrative-and-flow.md)。

## 微型示例

虚构转录：

- 主持人：“换了工具，是不是所有任务都快了？”
- 嘉宾：“嗯，开始感觉都快了……但复杂任务不能这么说，审核反而更久。”
- 后续同一嘉宾：“简单任务省时明显，复杂任务得单独看。”

可改为：

嘉宾认为，新工具对简单任务的提速比较明显。但主持人追问是否所有任务都变快时，他限定了这个判断：复杂任务可能需要更长时间审核，因此不能直接套用简单任务的结论。

不改成“新工具让所有任务提速”；也不把整理后的文字冒充嘉宾的一句原话。

整理时核对观点归属、提问条件与后续修正；统一审稿按主文件执行。
