# 长内容处理与实际效果评估

## 长内容：全局先行，分段成文，统一收束

当材料长到无法可靠地一次读取、定位和写作，或对谈与事件分支很多时使用。不要按固定字数机械切段。

1. **检查覆盖范围。** 确认正文或转录是否完整，工具输出是否被截断。长文件分批读到末尾；只有目录不能声称掌握全文。缺少部分内容时，明确已读范围，按实际范围交付或请求缺失正文。
2. **建立全局索引。** 记录已有章节、议题或事件区间及来源位置，标明主线、人物或说话者、关键概念和重要限制。这里先组织信息，不逐句润色。
3. **建立共用约定。** 统一人物称呼、说话者身份和术语译法；标出哪个概念首次解释、哪些观点在后文被修正、哪些事实在不同位置冲突。冲突需保留来源，不能为了统一而擅自消除。
4. **按主题或事件分段写。** 每一部分知道它接在什么之后、承担什么任务、将进入什么内容。涉及后文修正或跨段证据时回查原文。只为全篇写一次总开头和总收束，不让每个处理批次都产生独立引言、结论或术语表。
5. **做全篇编辑。** 按最终顺序通读，合并重复定义、同机制案例及反复总结，补必要承接，核对各部分的篇幅和主线关系，再回查重要事实与限制。

分段处理是内部方式，不默认把整篇改成连载。如果交付长度确需拆分，说明本次范围，不能把未交付或未核对的部分称为已经完成。用户要求完整详解时，不为缩短交付而省去尚未处理的主要议题。

## 实际评估：用四类材料检查表现

此流程用于技能评估和迭代，不强制每次文章改写都做。优先使用用户授权提供的真实材料；没有材料时可以准备评估方案，但不能把虚构示例或模型自评称为真实读者试验。无需为评估默认联系他人或外发文章。

建议首轮各选一份：

| 材料 | 应覆盖的难点 | 特别检查 |
|---|---|---|
| 采访或播客转录 | 话题跳转、重复、追问、修正或分歧 | 说话者与条件有没有错配 |
| 技术文章 | 概念依赖、机制或有顺序的操作 | 简化后是否失真，代码步骤是否准确 |
| 生活随笔 | 个人体验、感受或零散经历 | 是否被写成普遍规律或建议清单 |
| 纪实文章 | 人物关系、时间切换、多种来源 | 是否补造细节，来源与确定性是否改变 |

这四份是首轮覆盖建议，不是证明技能适用于所有文章。若混合内容或超长输入暴露问题，再补针对性材料，而不是无限增加类别。

### 每份材料如何评估

保留原文或其可定位来源、读者背景与篇幅要求、改写稿及使用的技能版本。没有版本号时可以记录评估日期及相关规则快照。只有用户需要保存评估记录时才创建文件，不默认复制、传播原文。

先做模型内部核对，标成“自检”：原意、关键内容、归属、条件、步骤及新增案例来源。定位到具体段落，避免用一个没有依据的总分替代问题描述。

有真实目标读者反馈时，再记录以下结果；读者可以是当前用户，不默认向其他人发送内容：

| 目标 | 怎样获取有效反馈 | 怎样记录 |
|---|---|---|
| 读得懂 | 请读者用自己的话复述核心事件、概念或判断 | 哪些理解正确、哪些遗漏或误解；不要求复述专业术语 |
| 跟得上 | 请读者指出需要回看、人物混淆或突然跳题的位置 | 具体段落和缺少的交代 |
| 愿意继续读 | 请读者指出开始跳读、感到重复或失去兴趣的位置及原因 | 区分实际阅读经历与仅对全文的印象；没有行为数据不编造读完率 |
| 保持原意 | 对照原文检查重要信息、确定程度和归属 | 具体遗漏、失真或无依据新增 |

自评可以发现阅读风险，不能证明真实读者愿意看完。格式校验只证明技能文件符合结构要求，也不能替代改写质量验证。

### 根据问题迭代

每轮优先修复最影响理解或准确性的问题，记录“出现在哪—为什么阻碍阅读—这次改了什么”。如术语过早出现就前移解释；案例太远就更换或删除；说话者混淆就修复归属；正文像讲评稿就减少不必要的“原文第几段”提示。

修订后重新检查相关片段及全篇衔接；改动公共规则时，用其他类型材料检查是否产生副作用。反馈只证明本次材料和读者的表现，不自动升级为所有文章都适用的硬规定。读者意见相反时记录背景差异，不靠继续增加模板解决。
