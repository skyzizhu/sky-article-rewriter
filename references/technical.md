# 技术说明、研究与教程

先判断读者要理解机制，还是完成操作。混合材料先补操作所需的最少解释，不顺带讲完整原理；公共写作、事实与审稿要求以主文件为准。

## 说明与研究

从技术解决的具体问题进入，按“这一环节处理什么、怎样处理、得到什么”解释核心流程，必要术语就近给出。复杂流程沿用同一任务，避免每节换例；区分实际流程与解释用的简化模型。只保留影响判断的适用范围、代价和不确定性。

研究材料分清对象、样本、方法、比较基准、结果与解释。相关关系不能写成因果，局部结果不能扩成所有场景；缺失的关键方法保留为缺口，不补造实验。

## 压缩时不能丢的区别

- **概念层次：** 相同名称不一定是同一机制。例如模型 KV cache、API 输入缓存与缓存计费相关，但不能互当同义词。读者只需理解账单时，讲清输入复用及计费即可，不补内部架构。
- **角色关系：** 模型、执行工具、服务提供方与付费方案分开交代；工具可能接入不同模型，订阅是付费或访问方式，不应把它们误写成互斥对象。
- **计量口径：** 数量、资源消耗与费用不互换；保留单位、时间、比较基准和费用范围。缓存命中不直接等于免费，输入、输出与累计处理量不混算。
- **执行条件：** 保留“什么条件下，做什么，得到什么”。例如 HTTP 304 需要放在条件请求核验的语境，不能写成“内容没变就一定返回 304”。一句必要条件不需要扩成整套教程。

有实际歧义才补最少澄清，不逐项罗列潜在误读。数字已说明关系时直接计算，不再叠加同机制的生活类比。

## 教程

按操作依赖排序，保留影响执行的环境、版本、权限、准备步骤及原文可确认的预期结果。命令、代码、参数、路径、单位保留精确形式；不为口语化改名或删参数。占位值注明示例性质，原文没给出的步骤或结果不猜。

大段原理不打断操作；缺失信息影响完成任务时就近指出，不能宣称教程已完整可运行。用户要求简短时先压解释，不删必要步骤。

改写不等于执行：未要求实际操作时不安装依赖或运行命令，不声称测试通过。疑似代码问题标明；需要修复时区分原版与修正版，并验证改动。新增或更新技术事实查阅官方文档，不把旧文悄悄改成最新版本教程。
