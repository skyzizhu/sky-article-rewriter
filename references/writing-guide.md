# 写作与案例选择指南

## 让读者一步步理解

识别障碍后再选解释方法，不默认每个术语都需要一个故事。

| 障碍 | 建议处理 |
|---|---|
| 概念陌生 | 日常语言释义 → 正式名称 → 必要时举例 |
| 因果跨度大 | 展开中间变化，区分确定关系与假设条件 |
| 相近概念混淆 | 明确各自含义，指出混淆会影响什么判断 |
| 数据难理解 | 说明口径、基数、时间范围及比较对象；缺失时指出缺失 |
| 缺少背景 | 补充理解本文必要的最少背景，避免旁支长篇介绍 |
| 结论过于概括 | 说明适用条件，以及现有材料无法覆盖的情况 |

允许先给结论建立方向，再展开解释；后续内容应增加机制、依据或边界，避免换句话重复。标题表达本节真正解决的问题，不强制全部写成问句。

口语化不等于故意碎句、过度使用“你想想”“说白了”，也不等于把读者当作儿童。保留术语中有用的精度，用具体语言解释它。

## 相似案例的选择

先用一句话写明需要解释的关系，例如“单次消耗下降，可能刺激使用量增加”。再检查候选案例：

- 主要参与者、变化方向、反馈过程是否能明确对应？
- 读者是否容易理解案例，还是需要先学习另一个复杂领域？
- 差异会不会破坏正在解释的机制？若会，放弃该类比。
- 案例是否比直接解释更有帮助？若没有，直接解释。

优先选择读者熟悉且对应清晰的案例，不按名气选择。同一个案例可解释相邻概念时可以沿用，减少频繁切换场景。

真实案例可以提供历史参照，但不同背景的结果不能直接预测本文情境。需要具体事实才能成立的真实案例，应查证权威或第一手来源，并在对应陈述附近引用。不能把概念模型包装成真实历史故事。

假设情境用于控制变量、解释机制。开头明确“假设”或“举个简化的例子”，数值仅作演示，不能当成实际统计。

## 不同文章的处理重点

- 观点评论：分开主张、论据和价值偏好；不要把作者立场包装成唯一答案。
- 科普说明：先给必要概念，再解释过程；简化后仍保留关键机制。
- 研究解读：分清研究对象、方法、结果与解释；区分相关关系和因果结论，不扩大样本适用范围。
- 新闻与行业分析：保留原文时间点；后续信息如需补充，要说明与原文的时间差，不悄悄改写为最新状态。
- 叙事与人物文章：维护事件顺序、视角与人物处境；主题理解可以有多种，不凭空推断人物动机。

## 支持深入阅读

把篇幅分配给决定结论的环节。例如“某现象是否普遍”取决于样本与口径，就解释证据范围；“为什么出现这个结果”取决于机制，就展开过程和替代解释。

用户要求带读、逐段讲解或确实需要回看时，可以在关键处提醒读者：“理解了这一点，再看原文中……就容易明白。”同时提供可核对的小节名或段落定位。不要虚构原文引句。

用户仅要求基于原文解读时，保留原文时点和主张归属；不要擅自扩展为全面事实核查。新增现实案例或影响结论的外部事实，仍须遵守核实和来源要求。

默认成稿是可独立阅读的文章。原文已提供足够具体的例子时先用原例，不再增加同结构的类比。多次解释同一机制时保留最清楚的一次，后文直接承接；必要来源提示集中处理，不把每一节写成对原文的评论。

## 从开场到结尾，始终围绕原文核心

写作前使用主文件中的核心记录。结构优化只改变读者怎样理解，不改变原文主要在表达什么。

### 具体开场与问题推进

优先检查原文已有的成果、场景、选择或反差，能否引出中心问题。例如原文整体评估一个模型的能力、成本和不足，可以从一段动画的实测结果切入，随后明确要回答的是“这个模型实际能完成什么，成本及不足怎样”，不能让全文变成只分析动画收费。

提纲阶段，为每节补一句“它接住了什么尚未解答的问题”。从成果进入工作过程，从过程进入费用机制，从结果差异进入能力限制，只是可能的路径；必须服从当前原文。一个问题无法覆盖全部核心议题时，保留相关分线，不强删内容来追求单线叙事。

成稿时移除这些内部问题标签，写成自然连接。不要每节都用设问开头，也不要用悬念拖延交代必要信息。

### 重点案例怎样选

先把候选案例对应到核心表达的不同部分，再选最能解释各部分的案例深入。只增加作品名称而没有新理解的案例合并简述；提供关键反例、不同对象或重要限制的案例即使不精彩也应保留。若全文本来是逐项教程或案例集，保留其独立项目，不为集中主线擅自删项。

对一个重点案例，先讲具体任务与结果，再说明它对原文判断的意义。原文没有记录的运行过程、人工投入、心理或原因，不得为了完整案例结构而补写。

### 标题检查示例

以下为虚构教学材料：原文评估“甲模型”，认为它在本次设计与游戏任务中费用低、结果已有可用性，加载合适 Skill 后部分表现改善，但精细度仍有限。

- 可用：“甲模型实测：低成本能做出怎样的作品，细节还差在哪里？”对象、方向与条件都有对应。
- 偏题：“AI时代，普通人如何抓住创作红利？”把模型实测换成了原文没有展开的人生建议。
- 失真：“甲模型全面超越顶级模型，几元钱取代设计师。”把局部评价扩大成绝对结论。
- 过窄：“缓存到底能省多少钱？”若作为整篇重构标题，会把支撑解释变成主题；只改写原文的费用部分时，明确范围后才可采用。

### 原文判断与延伸见解

同一虚构材料中，可以补充：“基于这些案例，可以进一步理解为，较低的调用费用降低了制作第一版原型的尝试成本。”这是解释者的推断，应保留其基于本次案例的范围。

不能顺势改成“所有创作者都应转用甲模型”，或让标题与结尾只剩“创作门槛消失”。即使一句延伸本身听起来合理，也不能替换原文对模型效果、费用与不足的主要表达。

结尾先准确收束原文的主要判断，保留其程度和条件；确有必要时再补一段紧密相关的延伸。没有新增价值就直接结束，不强加感悟。

### 最后一轮删减

重点删四类内容：第二次讲相同机制的类比；重复概括上段的总结；没有改变适用范围却重复出现的限定；与原文核心无关的泛化建议。删后再检查重要条件是否还在、观点归属是否清楚。边界说明应准确且适量，不能把原文积极评价悄悄改成处处否定，也不能为节奏好而删去实质问题。
